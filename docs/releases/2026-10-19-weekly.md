## New features

### Durable AI reviews

- Replaced the Flue review runtime with Pi Durable, retaining Microsandbox execution.
- Added per-conversation SQLite history, recovery, idempotent submission,
  app-owned HTTP snapshots and SSE, and read-only legacy history import.
- Added structured source search/read/diff tools, revision caching, and tool metrics.
- Consolidated one-click review controls and pull-and-continue flows.

### Ask AI and source navigation

- Select code to open an anchored Ask AI composer, with current, saved, or new
  conversation targets.
- Open filename and code references directly in an inline source viewer.
- Navigate immutable Git revisions, renamed paths, and sources available only in
  cached repositories. Ambiguous matches require a choice; approximate fallbacks
  carry a label.
- Turn findings into editable comment drafts without publishing on click.
- Added outside-click dismissal and Cmd/Ctrl+Enter submission behavior to editors.

### Background GitHub sync

- Comments, replies, approvals, edits, deletes, and thread resolution use a durable
  SQLite outbox. Browser IndexedDB holds drafts and submissions awaiting admission.
- Local admission frees the editor without waiting for GitHub. Pending work and
  recoverable text survive reloads and ordinary process restarts.
- SHA-256 content deduplication covers matching unsynced actions indefinitely and
  matching synced actions for 60 seconds, while preserving intentional replacements.
- Approval and inline-comment requests retain their reviewed commit and actor identity.
- Lost responses remain uncertain and reconcile against GitHub before any resend.
- One status icon beside the comment date replaces verbose sync panels: queued
  work pulses, sending spins, and warnings stay static. Details open on click.

### App updates and review context

- Added update detection and an in-app update notice.
- Improved CLI review/session context and handling of closed review tabs.

## Fixes

- Fixed production homepage and diff rendering.
- Limited persistent review SSE streams to two per origin, with polling fallback,
  preventing the reproduced HTTP/1.1 connection-starvation case.
- Kept read APIs available when the GitHub outbox cannot initialize; added safe
  database migrations and readable errors for empty proxy responses.
- Fixed duplicate draft submission after interrupted cleanup and separated reply
  drafts from edit drafts.
- Kept Ask AI available across background polling and code DOM replacement,
  while preserving exact selected text and source provenance.
- Fixed stale annotation metadata and deleted/resolved state reappearing from
  older local overlays.
- Preserved access to cancelled comments and deleted-comment text through history.
- Removed PR-list refreshes from comment/thread sync and coalesced related reads.

## Current behavior to know

- New background attempts require an active visible PR. Closing the app preserves
  queued work but pauses new attempts after its activity lease expires. Stopping
  the backend stops syncing.
- GitHub does not provide idempotency keys for comment/review creation. The outbox
  prevents blind retries but does not claim absolute exactly-once delivery.

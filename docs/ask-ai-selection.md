# Ask AI about selected source

## Design

- Select diff text or gutter lines, then choose the compact **Ask AI · Lines 9–33** bubble next to the selection. It has an accessible close icon, no LEFT/RIGHT UI jargon, and causes no source layout shift. Historical source uses the same bubble. Gutter selection still opens the existing comment form; asking AI does not submit or remove that comment.
- Geometry follows the actual highlighted text fragments at the selection endpoint (`Range.getClientRects` on selected text nodes), not whole code-row widths or the union of all selected lines. Backward selections use their starting fragment; gutter ranges anchor near visible source text. Positioning flips above/below and clamps within the viewport and code/source-modal bounds.
- Clicking Ask AI expands the bubble **in place** into **Ask about selection**: auto-focused question, conversation picker and send. The exact snippet/revision are available under a collapsed **Selected code** disclosure. The sidebar no longer renders a selection composer or opens merely because a selection is being discussed.
- Compact candidates dismiss on scroll/outside interaction/new selection/anchor removal. The expanded editor instead repositions or retains its last valid anchor, keeping the question, target and errors across scrolling, resizing, source collapse/unmount and outside clicks. New candidates cannot replace an open draft. Explicit Dismiss closes it; Escape may close a source modal or native picker but does not erase the editor.
- A native manual popover keeps both states above clipped diff containers. The expanded editor stays inside a historical-source modal's focus subtree; closing that modal relocates the portal to the page without losing App-owned draft state. It remains scrollable on narrow/short viewports.
- Pointer activation preserves native text selection. Keyboard users can select source or use source line buttons, then press **Alt+Enter** to focus Ask AI and **Enter** to expand it. **Escape** dismisses a compact candidate before closing a source dialog; expanded questions require explicit dismissal.
- ChatPanel exposes a typed live session/controller interface to the floating editor. Current/saved/new session orchestration, busy state and durable admission stay in ChatPanel—there are no duplicate APIs or session lists. The separate ordinary chat input is untouched. File, exact text, line range, side and source revision remain truthful in the quoted prompt even though internal side identifiers are not shown in the compact UI.
- Default to the current conversation; allow another saved conversation or a genuinely new one. New conversations receive only this question/context, not a generated review request.
- Use the existing durable review client. Reject busy/compacting destinations, serialize submissions, and retain the admission key and newly created destination after a lost response. Each explicit selection gets its own draft UUID: identical later questions are separate intents, not retries. Clear the selection only on durable admission or explicit dismissal.
- Explicit session creation always makes a fresh conversation, including while the active conversation is running or compacting. Automatic-review launches have a separate busy-session reuse policy.
- Freeze context at selection time. PR/diff/commit navigation invalidates the composer without deleting its draft; asynchronous create/history responses must not send stale context or switch the newly navigated page.
- Quote source as JSON and explicitly treat it as untrusted data. Maximum selection: 16,000 characters, with an explicit error instead of truncation.

## Revision and extraction rules

- Read gutter text from source coordinates, not virtualized DOM rows. Complete source arrays use one-based file coordinates, including expanded leading/trailing/inter-hunk context; patch-only arrays use hunk-relative coordinates and reject unavailable gaps. LEFT uses the old path on renames.
- Read native text selection using composed Shadow DOM ranges (with a shadow-local fallback). Preserve partial syntax-token selections. Reject cross-file, mixed-column and virtualized-gap selections.
- Unified context text has no unambiguous side: use its gutter instead.
- The core response captures head metadata around diff retrieval using fresh reads. A changed/unavailable head is not presented as a known source commit. PR comparison-base metadata is never called the merge-base.
- Commit LEFT is identified as the selected commit's parent; its SHA is explicitly unavailable. Historical source uses the actual source API ref.
- Full-PR expansion reports the actual fetched base/head refs, including that expanded LEFT source is comparison-base content. Existing commit expansion fetches full-PR content, so AI selection is rejected after that expansion; reload the commit patch to select it safely.

## Verification

- Node tests: patch/full-source extraction/renames/sides/hunk gaps, bounds, quoting/revisions, existing/new routing, busy/compacting rejection, creation/admission failures, per-draft idempotent retry, navigation races and double-clicks. The actual session router is tested with a busy active conversation: explicit creation is fresh and sends no automatic prompt, while automatic-review launches still coalesce.
- Browser-only extraction suite: from a Vite page, import `/src/lib/ask-ai-selection.browser.ts` and run `testSelectionInBrowser()` (8 checks) and `testExpandedSelectionInBrowser()` (24 checks using Pierre-rendered expanded split/unified source).
- Browser composer contract: import `/src/components/AskSelectionComposer.browser.tsx` and run `testBusyNewConversationInBrowser()` (11 checks). With a busy current conversation, two separately selected identical questions targeting New each create/admit once with distinct keys; admissions are mocked, with fresh backend creation covered independently by the real-router test.
- Bubble tests cover positioning/flipping/clamping, invalid/off-screen anchors, exclusive ownership and listener/frame cleanup. Import `/src/components/SelectionBubble.browser.tsx` and run `testSelectionBubbleInBrowser()` (16 checks) for real Shadow DOM Range geometry, native modal/top-layer placement, no layout shift, pointer/keyboard activation, toolbar arrow navigation, resize, scroll, selection replacement, host removal, exclusive bubbles, close/Escape and unmount.
- Expanded editor contract: import `/src/components/AnchoredSelectionEditor.browser.tsx` and run `testAnchoredSelectionEditorInBrowser()` (14 checks). Covers multiline endpoint alignment, compact → anchored editor, modal focus, collapsed snippet, busy/current/new targeting, double-click, failed receipt/retry key preservation, outside/scroll/resize draft preservation, portal relocation, stale navigation and truthful prompt context.
- Live Chromium validation covered an actual 25-line selection (lines 9–33): compact geometry follows the short final fragment rather than the wide multiline union, then a real mouse click expands in place and auto-focuses the question. Typing and choosing New exercised the production ChatPanel controller with intercepted HTTP responses: one create, a failed receipt, preserved draft/target across scroll/resize/outside click, then retry with the same admission key and successful dismissal. Resizing the open editor to 375×740 kept its controls inside the viewport and retained the draft/target. Historical-source modal focus and draft-preserving relocation were also validated against real source. No paid LLM request was made.
